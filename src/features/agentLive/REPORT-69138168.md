## The three rulings and their tests

**1. SDK behind the flag, development-live only, no SDK import when off.**
- JS: `room/livekit.tsx` is the only file that imports LiveKit. It is reached only by `await import('./livekit')`
  in `loadLiveRoomFactory()`, which the session screen calls only when the flag is on. With the flag off,
  `metro.config.js` resolves every LiveKit import to an empty module, so no SDK code goes into the bundle.
- Native: `plugins/agentLive`. On, it adds the LiveKit Expo plugin and the WebRTC config plugin. Off, the three
  native packages are not autolinked: `react-native.config.js` sets the RN modules' platforms to null, and
  `use_expo_modules!(exclude:)` / `expoAutolinking.exclude` exclude the Expo module. I ran
  `expo-modules-autolinking react-native-config` locally on ios and android. Off links no LiveKit or WebRTC
  module; on links both. `expo config --type prebuild` shows the right plugin list each way.
- Tests: `src/features/agentLive/__tests__/buildGate.test.ts` covers flag per profile (only development-live is
  true), plugin gate on/off, autolinking overrides, the Podfile/settings.gradle exclude (idempotent, and it throws
  on an unknown template rather than linking), the Metro stub regex, a source scan showing no static SDK importer
  outside the binding, and that loading `room`/`session` evaluates no SDK. `src/screens/AgentLive/__tests__/AgentLive.test.tsx`
  covers flag off: no Go live button, the screen renders a notice, no session started, no room loaded, no SDK
  module evaluated.

**2. Blind wire format, owner-only.**
- `blind.ts` sends exactly `{"t":"blind","on":true|false,"src":"*"|"<sourceId>"}`, key order fixed, no identity.
  It goes as a reliable data message on topic `stage.reply`. The session controller sends it only on a session
  the owner started and joined. The blind control on the session screen sends it for `"*"`. The worker side is
  piece 5's.
- Tests: `__tests__/blind.test.ts` (exact bytes, exactly the keys `t, on, src`, bad source ids refused, topic),
  `__tests__/session.test.ts` (sent on `stage.reply`, reliable; not sent before start, after a refused start or
  after end), and `AgentLive.test.tsx` (pressing the blind control sends the exact message).

**3. Identity: no DID or identity field leaves the app.**
- `api.ts` sends the bearer only. Bodies are built field by field: start is `{agentDid}`, token is `{camera}`, end
  has none. The query string is always empty. No `ownerDid`, `did`, `identity`, `tk`, `doId` or `handle`. Nothing
  logs a token, bearer or DID.
- Tests: `__tests__/api.test.ts` checks, for every call, that the query is empty and the owner DID is in none of
  the URL, body or headers. It also checks no identity key at any depth, the body keys exactly, that smuggled
  `ownerDid`/`identity` fields are dropped, that the token and end calls carry no `did:` at all, and that a
  network failure logs no token, bearer or DID.

## Assumptions (please confirm)

1. **`agentDid` stays in the start body** (qid `a61d98cf`, unanswered). Piece 1's route needs it to pick which
   agent goes live, and honours it only if the bearer's owner owns that agent. I read ruling 3 as "no owner
   DID and no identity field". If it means no DID of any kind, the runtime must choose the agent without
   one. Then drop the one field in `startLiveSession` and tighten the test to "no `did:` at all", as the token and
   end tests already do.
2. **The blind topic is `stage.reply`.** Addendum a760fdb1 didn't name a topic. `stage` is dropped from anyone
   but the agent, and `stage.reply` is the owner's stage topic in §1.3. It is one constant (`BLIND_TOPIC`).
3. **Native exclusion vs the brand golden** (qid `c90b77b4`, unanswered). Keeping the LiveKit native code out of
   off builds adds one plugin entry (`./plugins/agentLive/withAgentLiveExcluded.js`) to the flag-off app config.
   That changes all 72 hashes in `scripts/brand-config/base-config.golden.json`, so
   `scripts/__tests__/brandConfig.test.js` fails 3 tests. `golden.js` says not to regenerate the golden to make a
   compare pass, so I didn't. The two options:
   - (A, on this branch) keep it, and regenerate the golden in its own labelled commit once approved.
   - (F) drop the off-build exclusion, so the golden passes. The native libraries are then linked into every
     binary, and the Expo plugin's launch hook (`LivekitReactNative.setup()`) runs in production. I recommend A,
     because ruling 1 says production must not include the live path.
4. **Turning the camera on rejoins the room.** Piece 1 grants the CAMERA source only in a fresh token and doesn't
   update the connected participant. So the app gets a camera token, disconnects, reconnects with it, restores
   the mic, and only then publishes the camera. Turning it off unpublishes the camera track rather than just
   muting it.
5. **Subscriptions [L6].** `autoSubscribe` is off. The app subscribes only to `agent:<sid>:*`: its `stage` video
   (track name `stage`, or source screen share, as piece 1's grants describe) and its voice. The owner's own
   tracks are visible only to the agent identity.

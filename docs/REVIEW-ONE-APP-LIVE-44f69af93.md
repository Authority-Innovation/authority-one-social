### H2: FINDING, HIGH (partly closed)

Closed:

- Bearer pinned at start: `api.ts:105-114`, `:254-261`.
- `/end` called before disconnect: `session.ts:285-286`.
- Retry with backoff: `session.ts:239-252`.
- Stop decision made and tested: End is the stop path, and the runtime stops the job
  in `endSessionEverywhere`.
- Tests asked for pass: account switch and sign-out carry the original bearer, and
  `/end` failure is retried (`session.test.ts:519-566`).

Still open:

1. **"Show Ending until it resolves" is not met on the normal path.** `onEnd` calls
   `leave()` straight after `void controller?.end()` (`AgentLive/index.tsx:125-129`).
   The screen is gone before `/end` answers. `agentLiveEnding` can only appear if the
   Finished panel is still on screen.
2. **`/end` can give up silently.** After four attempts over about 11 s the loop just
   breaks (`session.ts:249-250`). Nothing tells the owner. The owner has left, but the
   agent is still in the room, so `empty_timeout` does not obviously fire. Scenario: tap
   End in a dead spot. The agent job can run to the session's hard end, and the only
   recovery is the "already open" prompt on the next visit.
3. **A 401 is not retried, and the pinned bearer can be stale.** `signed_out` breaks at
   once (`session.ts:243-248`). `LiveAuth.bearer` is fixed at start and never refreshed.
   After an account switch or sign-out, `bearerFor` falls back to it (`api.ts:254-261`).
   If that token has expired by then, `/end` gets a 401 and is never sent again.
   Reproduced with a throwaway test against the fake runtime: one `/end` call, phase
   `ended`, no error shown. It was not committed.
4. **The sign-out and account-switch hook asked for was not added.** The fix report says
   so (`REPORT-review-fix-2026-11-01.md:65-68`). On the current code the pinned bearer
   covers the common case: `logoutCurrentAccount` makes no `deleteSession` call
   (`src/state/session/index.tsx:184-218`), so a still-valid access token should keep
   working. That is from reading the code and is NOT VERIFIED against the PDS.

Smallest fix: keep the screen on Ending until `/end` resolves, with a visible failure
and a retry control; refresh the pinned bearer while the account is still current. Or
the owner may accept items 2 to 4 and downgrade; that is the owner's decision, not
this review's.

### M2: FINDING, MEDIUM

The client asked-for parts are done: "Continue here" prompt (`session.ts:539-541`,
`AgentLive/index.tsx:284-325`), and `DUPLICATE_IDENTITY` reads as moved to another
device (`session.ts:370-375`).

But the move the prompt offers is refused by the runtime when the first device is still
connected. Keys are per device, and `mayReplace` needs the same pinned key
(`live-tenant-do.js:301`, `:317-321`). So device B's token is `duplicate_identity`
unless device A's `participant_left` lands first; the code comment says the order can go
either way.

Expected result from reading the code, NOT VERIFIED on devices: device A ends with
"moved to another device", device B is removed with "You were removed", neither sends
`/end`, and the session stays open with the agent in it. Needs a runtime or product
decision. The copy at `AgentLive/index.tsx:298-301` promises a move that may not happen.

### New findings

**N1, MEDIUM: a final disconnect during a rejoin is swallowed.** `onConnection` returns
early while `rejoining` is true (`session.ts:358`), and `rejoining` stays true through
the mic and camera steps (`:432-437`, `:645-661`). That window is when a runtime refusal
of the fresh join would arrive, since `participant_joined` removes at once.

- Reproduced with a throwaway test: drop `network`, then `removed` during the mic step.
  Final state `phase: connected, micOn: true`, which is the "Mic on" on a dead room that
  H1 and R2 forbid. It was not committed.
- The fake room resolves the mic call. Read against the SDK, I expect mic-on to stall
  and throw, then retry, so the final reason is lost rather than the UI lying. Mic-off
  resolves at once, so a muted owner could be left on a dead "connected" screen. Both
  are PLAUSIBLE, NOT VERIFIED on a device.
- Not changed by 95b57da75.

**N2, MEDIUM: the consent reply's `agent` field is ignored.** The runtime returns
`not_started` or a job failure reason (`live-consent-routes.js:134-141`). `readConsent`
drops it (`api.ts:381-391`), though the file's own header lists it. If the job fails to
start, the owner joins an agentless room, mic on, and sees "Waiting for your agent's
stage…" with no timeout (`AgentLive/index.tsx:462-466`).

**LOW:**

- Unbound rejoin: with no device key (keystore failure) a fresh token is
  `duplicate_identity` until `participant_left`, and R2 says the client must wait. The
  app ends with "removed". The fix report's "R3 not needed" holds only for bound tokens.
- `setCamera` can mint a token for a session that already ended: `session.ts:625` falls
  through when `over()`. The token is discarded at `:630`.
- Blind is not re-sent after a rejoin; the UI keeps `blindOn`. Harmless only if the agent
  keeps its state (not checked).
- No mid-session consent withdrawal control (the fix report says so); the runtime route
  exists.
